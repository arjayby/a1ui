"use client";
import { useState } from "react";
import { ActionApproval, type ActionApprovalProps } from "@/components/ui/action-approval";

export function ReviewAction() {
  const [status, setStatus] = useState<ActionApprovalProps["status"]>("pending");
  return (
    <ActionApproval
      action={{
        id: "action-1",
        revision: 1,
        title: "Create a draft",
        tool: "write_file",
        input: { path: "draft.md" },
      }}
      status={status}
      onDecision={(decision) => setStatus(decision.decision)}
    />
  );
}

## API reference

| Prop           | Type                                                  | Purpose                                                                                                                |
| -------------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `action`       | `ProposedAction`                                      | Required. `id`, numeric `revision`, `title`, `tool`, JSON-serializable `input`, optional `description` and `impact`.   |
| `status`       | `"pending" \| "approved" \| "rejected" \| "expired"`  | Required controlled lifecycle. Pending means awaiting a decision.                                                      |
| `onDecision`   | `(decision: ActionDecision) => void \| Promise<void>` | Required. Receives `actionId`, `revision`, `decision` and trimmed `note`. Resolve only after the decision is recorded. |
| `decisionNote` | `string`                                              | Optional persisted note for resolved requests.                                                                         |
| `disabled`     | `boolean`                                             | Defaults to false. Disables both decisions and the note.                                                               |
| `className`    | `string`                                              | Layout classes.                                                                                                        |

`ActionDecision.decision` is `approved` or `rejected`. Notes are optional and limited to 2,000 characters. Pending saves lock both buttons. Failures retain the note and allow retry. A successful callback locks the request locally even before the host updates its status. Resolved and expired requests do not offer decision controls. A new action ID or revision resets local state.

Tool inputs are escaped JSON text, never executed as code or interpreted as HTML. Keep inputs to plain serializable data. If serialization fails, approval is disabled and rejection remains available. The inputs panel is expanded by default and can be scrolled with the keyboard. Do not hide relevant effects in the description; use `impact` to state what the tool would change.

## Template integration

The reference template handles tool parts in `components/chat-message.tsx` and `components/parts/`. Add a typed approval part and render this component there. Do not map `input-streaming` to a decidable request: wait until all validated inputs are available. Assign the tool call's stable identity and a new revision when its inputs change.

Use your AI SDK's approval response mechanism if your tool uses native approval, or a validated application endpoint for a custom workflow. The existing `ask_user` questionnaire uses `addToolOutput`; it is not itself a secure authorization system. Adapt the result explicitly rather than passing an approval UI state directly to a tool.

The server must authenticate the decision, check the stored action ID, revision, inputs and expiry, and reject stale or duplicate execution. An approved display records consent; it does not guarantee execution. Stream tool execution and failures separately. The example intentionally has no tool executor or backend.
